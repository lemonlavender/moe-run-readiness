# MoE 训练运行就绪审查

[English README](README.md)

MoE Run Readiness 是一个可复用的智能体 Skill，用于在投入稀缺加速器资源前审查混合专家模型训练方案。它把运行材料整理为证据分级的就绪判定、拓扑台账、系统风险矩阵和分阶段验证阶梯。

## 解决的问题与目标用户

大型 MoE 训练可能因单一利用率数字或一次冒烟测试无法暴露的问题而失败：Rank 归属不完整、专家流量倾斜、新序列形状耗尽显存余量、多节点 all-to-all 占据主要步时，或检查点写入成功却无法恢复。本 Skill 帮助模型系统工程师、研究基础设施团队、技术项目负责人和算力审批人依据已有证据审查这些风险。

## 适用场景

- 在预订整组集群前审查 GPU 分配方案。
- 核对数据、专家、流水线和张量并行维度。
- 识别路由、通信、显存和检查点证据缺口。
- 仅在输入与环境匹配时比较精度实验。
- 把智能体生成的“已就绪”建议转换为有边界、可由人工复核的交接报告。
- 明确下一步可安全执行的最小阶段及其停止条件。

## 已实现功能

- 三种就绪判定：`ready-for-staged-run`、`conditional`、`blocked`。
- 四类证据：`observed`、`derived`、`claim`、`unknown`。
- 显式检查 world size 与 Rank 归属关系。
- 覆盖路由、显存、精度、通信、恢复、数据形状和可观测性的系统矩阵。
- 从配置审查到算力审批的七个有序验证阶段。
- 每个阶段包含流程、预期证据、负责人和停止条件。
- 固定边界：分配生产规模算力前必须完成人工审批。

## 工作流程

1. 收集运行 ID、版本、完整解析配置、硬件清单、模型与路由形状、并行维度、数据与批形状、精度模式、基准结果、检查点结果、负责人和预算约束。
2. 以 Markdown 或附件文本提供材料。
3. 明确要求智能体使用 **MoE Run Readiness**，且不执行命令。
4. 审查就绪判定和下一允许阶段。
5. 确认拓扑台账覆盖每个 Rank 和专家放置。
6. 为缺失材料和验证阶段分配负责人。
7. 后续执行仅在责任团队的控制下进行，任一闸门失败即停止。
8. 只有分阶段证据与检查点恢复通过人工复核后，才申请算力审批。

## 环境要求

- 声明式安装路径要求 [iPolloWork](https://github.com/Devin-AXIS/iPolloWork) 0.50.12 或更高版本。
- 桌面验收流程使用本地 OpenCode 引擎项目。
- 以文本或文件提供运行材料。
- 审查本身无需外部账号、API Key、集群连接或安装训练框架。

本 Skill 不会启动任务、执行命令、预订硬件、修改调度状态或验证模型质量。

## 输入与输出

### 输入

- 运行身份、版本、框架和完整解析配置；
- 节点、加速器、显存和互连信息；
- 模型规模、专家数量、top-k 路由和容量行为；
- DP、EP、PP、TP 与 Rank 映射；
- 序列长度、Token 批量、Microbatch、梯度累积和数据集身份；
- 精度模式与数值证据；
- 吞吐、步时、显存、路由、通信和 Rank 偏差指标；
- 检查点写入和恢复证据；
- 规划建议、负责人、预算与调度约束。

### 输出

一份 Markdown 交接报告，包含就绪判定、来源表、拓扑台账、系统证据矩阵、证据台账、七阶段验证阶梯、状态变更闸门和未解决输入。

## 端到端示例

[`examples/run-packet.md`](examples/run-packet.md) 提出在一次 8 GPU 冒烟测试后执行 64 GPU、64 专家训练。材料包含较高利用率和较好的路由辅助损失，但缺少每专家 Token 分布、多节点通信试验、同输入 MXFP8 对比、准确启动命令和检查点恢复证据。

调用示例：

```text
使用 MoE Run Readiness 审查 examples/run-packet.md。不要联网或执行命令。保留所有提供值，进行证据分级，并保存完整 Markdown 交接报告。
```

预期结果为 `blocked`。拓扑算术看似可行，但缺少完整解析配置、可操作的显存余量、精度对比和恢复证据，因此任何执行阶段都不能开始。立即预订全部 GPU 的建议保留为 `claim`；下一允许动作仅为配置审查。参见 [`examples/expected-readiness.md`](examples/expected-readiness.md)。

## 在 iPolloWork 中使用

1. 从 GitHub Release 下载 `moe-run-readiness-1.0.0.ipollowork-plugin`。
2. 在 iPolloWork 打开 **扩展 → 插件 → 添加 → 文件**。
3. 选择安装包，确认发布者为 `lemonlavender`、版本为 `1.0.0`，并包含一个 Skill 资源。
4. 安装后启用插件和 **MoE Run Readiness** Skill 开关。
5. 打开本地 OpenCode 项目并加入运行材料。
6. 明确要求智能体使用 **MoE Run Readiness**，确认它加载 `SKILL.md`、`readiness-rules.md` 和 `report-format.md`。
7. 审查并导出生成的 Markdown 交接报告。

独立导入时，解压 `moe-run-readiness-1.0.0-skill.zip`，在本地 Skill 导入界面选择其中的 `moe-run-readiness` 文件夹。GitHub URL 不是通用安装方法。

## 构建与打包

只需 Node.js 22，以及系统自带的 `zip`、`unzip`、`shasum`：

```bash
npm run package
npm test
cd dist
shasum -a 256 -c SHA256SUMS.txt
```

构建会生成 iPolloWork 直接安装包、独立 Skill ZIP、单独源码 ZIP 和校验文件。安装包根目录包含一份 schemaVersion 2 清单及完整 Skill 目录。

## 常见问题

### Skill 会运行训练任务吗？

不会。它只审查提供的证据并输出计划。后续命令由工程师在获准环境中执行。

### 并行度算术一致就能证明可以扩展吗？

不能。它只完成一项一致性检查。多节点通信、Rank 偏差、路由分布、显存、数值稳定性和恢复仍需分阶段证据。

### 高 GPU 利用率足够吗？

不够。它可能掩盖热点专家、all-to-all 停顿、慢 Rank、重试或不合适的测量窗口。Skill 会要求可归属的时序指标和路由证据。

### 智能体给出的“生产就绪”标签能批准算力吗？

不能。在证据闸门与人工复核完成前，它只是一条 `claim`。

### 启动命令缺失时怎么办？

交接报告会要求收集并记录准确流程，不会编造命令。
